\textbf{Abstract.}
One weight file serves eight quality settings. The usual method uses one precision for all parts of the
model. That method ignores an imbalance. The encoder holds 85.6\% of the parameters. The entropy model
takes most of the decode time. The decoder is small, but it contains a fragile part.
We measure how much each of 19 parts tolerates seven number formats. The measurements cover eight
quality settings and two datasets: 69,233 results.
A mixed-integer linear program (ILP) then chooses one precision for each part.
The result is \best{21.677 MB}, against 54.688 MB in FP32: a \best{60.4\%} size reduction at a
\best{0.94\%} worst-case quality loss. The B{\o}ntegaard delta-rate (BD-rate) is $+0.48$ to $+0.55\%$ on
three datasets. Compare this with the simple baseline: uniform INT8 gives a smaller file of 13.904 MB,
but its loss is 26.18\%. At the same size, the mixed assignment is \best{39$\times$} better in quality.
Finally we test quantization-aware fine-tuning (QAT). QAT removes \best{61--98\%} of the damage on
hand-chosen assignments. It removes \best{0\%} on the assignment that the solver optimized.
Therefore QAT repairs the cost that an assignment leaves. An optimal assignment leaves none.

\section{Introduction}
A learned image codec stores its weights in one file. In PULSE~\cite{pulse}, that file serves eight
quality settings and holds 14.18M parameters, or 54.688 MB in FP32.
A team that wants a smaller file usually applies post-training quantization. The usual method uses one
precision for the complete model, because a study of each part takes time.
That method is a loss for this model. The parts are not equal. The encoder holds 85.6\% of the
parameters. The entropy model is only 9.4\%, but it takes 73\% of the decode time. The decoder is 5.0\%,
and one of its blocks has 4.7k weights that lose 8\% at 8 bits. A larger encoder block with 2.89M
weights loses only 0.5\% at the same precision. Sensitivity does not follow size.

We therefore ask three questions.
\textbf{(Q1)} Which parts tolerate which precision, and at which quality setting?
\textbf{(Q2)} Which assignment is the smallest that stays below a quality limit?
\textbf{(Q3)} Can fine-tuning recover the remaining loss, and where does it stop?
A fourth question was not in our plan. It became the most useful one: why does quantization not make
this codec faster?

\section{Prior work}
Integer quantization with one scale per output channel is standard practice~\cite{jacob}. A
straight-through estimator supplies the gradient through the quantizer~\cite{bengio}. PULSE provides the
codec that we study~\cite{pulse}. We state the allocation problem as an ILP and solve it with
HiGHS~\cite{highs}.
For the rate-distortion comparison we use the BD-rate~\cite{bjontegaard}. We make one change to that
method. The original method fits a curve through four points. We have eight points, so we use monotone
piecewise-cubic interpolation~\cite{pchip}.

\section{Idea and implementation}
\subsection{Measurement of sensitivity}
We quantize one part at a time. All other parts and all activations stay in FP32. We then run the
complete codec on each image at each quality setting.
The plan covers seven number formats, 19 parts, two datasets and eight quality settings. The datasets
are Kodak~\cite{kodak} for screening and CLIC Professional~\cite{clic} for confirmation. We collect
69,233 rows. No run failed, and a hash check confirms each weight restoration.
An FP32 gate compares the bitstream and the reconstruction with the reference. The gate must pass at
all eight settings before we accept a row. Thus each difference comes from the quantized part, and from
no other cause.

We use a rate-equivalent penalty to combine a quality change and a bitrate change in one number:
\begin{equation}
\text{penalty}=100\left[\left(1+\tfrac{\Delta\text{bpp}}{100}\right)2^{-\Delta\text{PSNR}/\sigma}-1\right],
\end{equation}
where $\sigma$ is the local slope of the reference curve. A value of zero means the model is
indistinguishable from FP32. The ILP limits the worst setting. The worst setting is the maximum over
the eight settings of the mean over the images.

The ILP adds the costs of single parts. That step is correct only if the costs are additive. We tested
this condition. Divide the measured penalty of a uniform INT8 model by the sum of the 19 single-part
penalties. The ratio is 0.96 to 1.05 on Kodak and 1.02 to 1.11 on CLIC. The costs are additive.
One warning: do not add the worst setting of each part. That sum gives 65.3\%, but the true value at one
setting is 26.7\%. Add the costs for one setting, then take the maximum.

\subsection{The allocation problem}
One weight file serves all eight settings. A different assignment for each setting is therefore not
deployable. The model has one binary variable for each pair of a part and a format. Each variable is
shared by all settings. The model has one quality constraint for each setting:
\begin{equation*}
\begin{aligned}
\min\;&\textstyle\sum_{c,f}\text{size}(c,f)\,x_{c,f}\\
\text{s.t.}\;&\textstyle\sum_{c,f}\text{pen}(c,f,q)\,x_{c,f}\le \epsilon \quad \forall q\in\{0,\dots,7\}\\
&\textstyle\sum_{f} x_{c,f}=1 \quad \forall c .
\end{aligned}
\end{equation*}
The objective is the number of bytes. It is not latency. We have no measured latency table for each
format on this GPU. An objective that used such a table would optimize data that we invented.
We also solve a greedy baseline for comparison.

\subsection{Quantization-aware fine-tuning}
QAT applies quantized convolutions with a straight-through gradient. It then minimizes distortion and
holds the bitrate at its pre-quantization value.
A fixed rate penalty failed in both directions. A weak penalty lets the model move down the
rate-distortion curve. A strong penalty destroys quality to obey the rate target. We use an augmented
Lagrangian instead. The multiplier $\mu$ comes from the measured rate error on a fixed validation set:
\begin{equation*}
\mathcal{L}=\frac{D}{D_{\text{ref}}}+\mu\left(\frac{R}{R_{\text{ref}}}-1\right),\qquad
\mu\leftarrow\mathrm{clip}\!\left(\mu+\alpha\,e_{\text{rate}}\right).
\end{equation*}
We freeze the entropy parts. The bundle contains integer cumulative distribution function (CDF) tables.
If the entropy weights move, those tables no longer describe the weights, and the encoder and the
decoder disagree.
The saved checkpoint must be better than its own start. If it is not, we keep the start weights. A bad
run therefore cannot ship a worse model.
Training uses 100 DIV2K images~\cite{div2k}. These images are disjoint from all test sets. We run 12,000
steps on 512-pixel crops, which takes about 100 minutes for one tier on one 4\,GB laptop GPU (PyTorch
2.6, CUDA 12.4, HiGHS via SciPy). This work uses 2.2\% of the optimizer steps and 0.2\% of the sample
budget of the pretraining~\cite{pulse}. Thus it is a repair operation, not a new training.

\subsection{Comparison with the baseline}

This is the best evidence that the assignment transfers.

quality and stability.

\subsection{Effect of QAT}
Table~\ref{tab:qat} answers Q3. QAT removes 61\% to 98\% of the damage on assignments that a person
chose. It removes no damage on the assignment that the solver optimized. This result is the useful one.
Fine-tuning replaces a good allocation; it does not extend it. The assignment decides the size of the
repair. An ILP that already minimized the total damage leaves almost no damage to repair.

\subsection{Absence of a speedup}
No configuration was faster than FP32. We used paired interleaved benchmarking with 50 pairs for each
cell. The mixed model is 4.79\% slower (95\% confidence interval $+1.27$ to $+9.80$). Its energy change
is $-0.39\%$, and the interval includes zero.
The cause is arithmetic. A decode takes 88\,ms. Entropy coding takes 80\,ms of that time, and the
convolutional network takes 8\,ms. Quantization makes convolutions cheaper. Convolutions are 9\% of a
decode and 27\% of a round trip.
We make no speed claim for FP8, INT4 or FP4. These formats run as simulated quantization here. Only FP16
and BF16 use real kernels on this GPU, and they save energy, not time.

\section{Conclusion}
Granularity is the lever, not precision. At the same size, mixed precision is 39 times better than
uniform precision. QAT replaces a good allocation and does not extend it. QAT removed 61\% to 98\% of
the damage on hand-chosen assignments, and 0\% on an optimal one. Both results are necessary. The second
one is visible only because we measured the control case.

\subsection*{Limitations}
(a) Our checkpoint selector gives a low estimate of the QAT gain. A probe with 6 crops rated the best
INT8 model as equal to its start ($-0.08\%$). The full evaluation shows 8.61\% to 3.36\%. The saved
checkpoints are thus probably not the best available.
(b) We quantize weights only. Activations stay in FP32, so we do not test W8A8.
(c) The 4-bit formats are simulated, so we do not measure their speed.
(d) The entropy coder uses one lane. This is the largest unused latency lever.
(e) The QAT results use one seed and 100 images. The qualitative result holds for three tiers and two
step counts. The exact percentages are single-run values.
